# ADR-001 - Initial Technology Stack and Architecture

## Status

Accepted

## Context

The Chronicles is a private, collaborative digital memory archive.

The application needs to support:

- Multiple chronicles per user
- Shared membership and permissions
- Collaborative memory management
- Real-time synchronization
- Photo storage
- Interactive timeline functionality
- Future growth without unnecessary initial complexity

The project is developed incrementally, with a local-first development approach.

## Decision

The project will use a modular monolith architecture with the following technology stack.

### Frontend

- React
- Vite
- TypeScript

### Backend

- ASP.NET Core Web API
- C#
- Modular Monolith architecture

### Database

- PostgreSQL
- Entity Framework Core

### Communication

- REST API for standard application operations
- SignalR for real-time communication

### Authentication and Authorization

- ASP.NET Core Identity
- JWT
- Resource-Based Authorization

### File Storage

- Separate photo storage
- Local storage during initial development
- Cloud Object Storage as the long-term direction

### Testing

- xUnit
- Vitest
- React Testing Library

### Development Environment

- Windows
- Docker Compose
- Local frontend and backend processes
- PostgreSQL running in Docker

### Repository

- Monorepo
- Separate frontend and backend applications

## Rationale

### Modular Monolith

A modular monolith provides clear internal boundaries without the operational complexity of microservices.

It is appropriate for the current project size and allows modules to evolve independently.

### React + Vite + TypeScript

This combination provides a straightforward frontend development environment.

Server-side rendering is not currently required by the product.

### ASP.NET Core

ASP.NET Core provides a mature backend framework with strong support for APIs, authentication, authorization and SignalR.

### PostgreSQL + Entity Framework Core

PostgreSQL provides a reliable relational database.

Entity Framework Core integrates naturally with the .NET backend and supports migrations and database operations.

### REST API + SignalR

REST API handles standard data operations.

SignalR provides real-time communication required for collaborative chronicle updates.

### ASP.NET Core Identity + JWT

Identity provides established user management and password security functionality.

JWT provides API authentication.

### Docker Compose

Docker Compose makes local infrastructure reproducible.

Starting with PostgreSQL in Docker keeps the initial environment manageable.

### Monorepo

A single repository simplifies project coordination, documentation and version control.

## Consequences

### Positive

- One consistent technology stack across the backend.
- Clear business module separation.
- Straightforward local development.
- Real-time functionality supported from the beginning.
- Infrastructure can evolve independently.
- No unnecessary microservice complexity.

### Trade-offs

- Module boundaries must be maintained through development discipline.
- JWT security configuration requires careful design.
- Real-time synchronization and concurrent editing require additional engineering.
- Production hosting and storage infrastructure still need to be selected.

## Future Decisions

The following decisions are intentionally outside the scope of this ADR:

- Detailed database schema.
- API contracts.
- Offline synchronization implementation.
- Cloud storage provider.
- Production hosting and deployment.

These will be documented separately when approved.

## Implementation Rule

This ADR records the approved architectural direction.

Implementation must follow this decision unless a new architectural decision explicitly supersedes it.

Unresolved details must not be treated as approved requirements.
